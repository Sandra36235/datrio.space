02 / Antes del modelo

Conoce los ingredientes.

No elijas un algoritmo contando columnas. Primero identifica qué representa cada fila y qué necesitas obtener.

Una fila = un ejemplo

Puede ser un cliente, una compra, una sucursal por mes o un producto por día. Mezclar niveles sin cuidado puede duplicar importes y distorsionar el análisis.

Una columna = una característica

X es la información que usas: antigüedad, precio, categoría… Y es la respuesta que quieres predecir, cuando existe.

Ejemplo: predecir gasto.
X = antigüedad y tipo de contrato.
Y = gasto del siguiente periodo.

¿Una, dos o muchas variables?

Con una entrada puedes construir un modelo; con veinte también. La cantidad no decide si el problema es clasificación o regresión.

Importan la calidad, el número de filas, las categorías, los valores faltantes y si esas variables estarán disponibles cuando uses el modelo.

En pronósticos: una sola serie puede usar su propio pasado. Agregar promociones o clima exige conocer sus valores futuros o construir escenarios.

El examen debe tener preguntas nuevas.

1Entrenar: aprender patrones2Validar: elegir ajustes3Probar: evaluación final

Usa los mismos conjuntos para comparar modelos. La limpieza que aprende valores —como rellenar con una media o ajustar escalas— se aprende solo con entrenamiento.

Si predices el futuro, respeta el tiempo: aprende del pasado y evalúa en fechas posteriores. Si hay varias filas del mismo cliente, evita que su información se cuele entre conjuntos cuando eso haga la evaluación irreal.

03 / Laboratorio de clasificación

Una alarma. Dos maneras de equivocarse.

Positivo significa el evento que buscas: abandono, impago, compra o fraude. Aquí buscamos clientes que abandonarán. Los datos son ficticios para aprender.

FP: una falsa alarma

Predices «se va», pero se queda. Podrías gastar una oferta innecesaria.

FN: un caso que se escapó

Predices «se queda», pero se va. Podrías perder una oportunidad de retenerlo.

Mini reto: marcaste una compra como fraude, pero era legítima. ¿Qué error es?

Mueve el punto de corte

El umbral decide desde qué riesgo marcas al cliente. Los riesgos no cambian cuando mueves el corte.

20 clientes de ejemplo · 6 abandonan realmente · 14 se quedan.

Muéstrame las fórmulas, despacio

Recall = VP / (VP + FN). De todos los positivos reales, cuántos encontraste. El denominador incluye los casos que se escaparon.

Precision = VP / (VP + FP). De todas tus alertas, cuántas eran correctas. El denominador incluye las falsas alarmas.

Accuracy = (VP + VN) / total. Cuántas respuestas acertaste, incluyendo positivos y negativos.

F1 = 2 × precision × recall / (precision + recall). Combina ambas; no representa dinero ganado ni sustituye evaluar los costos.

Si un denominador es cero, mostramos «No definida». Algunas bibliotecas muestran 0 por convención: pide que se documente.

La trampa: decir «nadie abandona» acertaría con 14 de estos 20 clientes: 70 % de accuracy y 0 % de recall. Muchos aciertos no garantizan utilidad.

05 / Interpretar sin adivinar

El resultado tiene que contestar tu pregunta.

Cómo leer una comparación de modelos

  1. Busca la referencia: ¿supera una regla simple como el promedio, la clase mayoritaria o el último periodo?
  2. Comprueba el examen: ¿se evaluaron con los mismos datos nuevos y la misma información disponible?
  3. Lee la métrica adecuada: ganar en una columna no significa resolver mejor el negocio.
  4. Mira la variación: pequeñas diferencias pueden cambiar con otra muestra. Pide intervalos o resultados por partición.
  5. Traduce a operación: ¿cuántas alertas revisarás, cuánto error toleras y qué acción puedes ejecutar?

Una variable importante ayuda al modelo a predecir. Eso, por sí solo, no prueba que cambiar esa variable cause un cambio en el resultado.

A mano / Diccionario y fuentes

Traducciones del idioma técnico.

Modelo, algoritmo y entrenamiento

El algoritmo es el procedimiento para aprender. El entrenamiento es ese proceso. El modelo es el resultado aprendido que después usas con nuevos casos.

Supervisado y no supervisado

En aprendizaje supervisado tienes ejemplos con la respuesta, como gasto o abandono. En no supervisado buscas estructuras sin una respuesta objetivo conocida, como agrupaciones de clientes.

Regresión logística: ¿por qué sirve para clasificar?

Aunque lleva «regresión» en el nombre, se utiliza para estimar probabilidades de categorías. Con un umbral esas probabilidades se convierten en decisiones de clasificación.

Sobreajuste y fuga de información

Sobreajuste: el modelo aprende peculiaridades del entrenamiento que no se repiten en nuevos datos. Fuga: recibe pistas que no tendría al usarlo, directamente o durante la preparación de los datos. Ambos pueden producir evaluaciones engañosas.

Escalar, codificar y regularizar

Escalar pone variables numéricas en magnitudes comparables. Codificar convierte categorías en representaciones que el modelo puede procesar. Regularizar limita la complejidad para reducir el riesgo de aprender ruido. La necesidad depende del modelo.

Probabilidad estimada e incertidumbre

Un riesgo de 80 % no es una certeza individual. La calibración comprueba si grupos con riesgos similares presentan frecuencias parecidas. Los intervalos muestran un rango plausible bajo los supuestos del método; no son una garantía.

Forecasting univariado y múltiples variables

Un pronóstico univariado usa el historial de una serie. Se pueden agregar variables explicativas como promociones. Predecir varias series relacionadas es otro diseño: tener muchas columnas no obliga a usarlo.
